# 用户需求记录

## 2026-06-12 - Bug 修复和新功能需求

### 用户原话

1. 配置向导页面，点击保存配置，依旧还是一直显示正在保存，我也不知道他到底是保存了还是没保存，可能是保存还是有问题
2. 不知道是我点了保存配置之后的问题，还是什么问题我明明是已经登上了状态，但是他在每次检测之后会发一个通知，说是重连成功，但是其实我是一直处在连接状态
3. 新增一个功能就是禁用通知，就是如果勾了这个选项之后，禁用全部的通知
4. 菜单栏检测间隔，它的对号不能实时同步

### 问题分析

**问题1：配置向导保存无反馈**
- 原因：`saveConfig` 函数成功后没有显示消息，也没有跳转到完成步骤
- 逻辑链：前端 → `/api/save-config` → 保存配置 → 返回成功 → 前端没有处理

**问题2：重复通知"重连成功"**
- 可能原因1：Detect() 函数误判为离线
- 可能原因2：登录后状态未正确保持，下次检测又变成离线
- 可能原因3：检测间隔太短，频繁触发
- 逻辑链：检测 → 判断状态 → 触发重连 → 通知 → 再检测 → 又判断为离线 → 循环

**问题3：禁用通知功能**
- 需要在配置中添加 `DisableNotification` 选项
- 修改 `showNotification` 函数，检查是否禁用

**问题4：检测间隔对号不同步**
- 原因：`setInterval` 函数没有更新菜单项的勾选状态
- 逻辑链：点击间隔 → 更新配置 → 发送 channel → 但没有更新菜单 ✓

### 提取的需求清单

1. **配置向导保存反馈** - 保存成功后显示成功消息，并跳转到完成步骤
2. **修复重复通知问题** - 分析并修复检测逻辑，避免误判
3. **禁用通知功能** - 添加禁用通知选项，勾选后不发送任何通知
4. **检测间隔对号同步** - 切换间隔后实时更新菜单项的勾选状态
