# 框架 UI 对比

## 说明

已收集的截图见各子目录，主要是 GitHub 项目页面和文档页面。
以下用文字+代码详细描述每种方案做出来的实际 UI 效果。

---

## 方案 A：Go + walk（Windows 原生 Win32 控件）

### UI 风格描述

walk 是 Go 语言的 Windows GUI 库，直接调用 Win32 API，做出来的界面就是**经典 Windows 风格**：

- **窗口**：标准 Windows 窗口样式，标题栏、最小化/最大化/关闭按钮
- **按钮**：Win32 原生按钮，灰色背景，鼠标悬停有轻微高亮
- **输入框**：标准 Windows 文本框，白色背景，蓝色选中高亮
- **下拉框**：标准 ComboBox，点击展开列表
- **复选框/单选框**：标准 Windows 样式
- **菜单**：标准 Win32 右键菜单，白底黑字
- **托盘图标**：系统托盘区域显示图标，右键弹出菜单

### 视觉特点

```
┌─────────────────────────────────────┐
│  校园网自动保活工具          ─ □ ×  │
├─────────────────────────────────────┤
│                                     │
│  账号: [________________]           │
│  密码: [________________]           │
│  运营商: [校园用户      ▼]          │
│                                     │
│  检测间隔: [30] 秒                   │
│                                     │
│  ☑ 开机自启                         │
│                                     │
│       [保存设置]  [测试登录]         │
│                                     │
│  状态: ● 在线                       │
└─────────────────────────────────────┘
```

**优点**：
- 100% Windows 原生外观，与系统完美融合
- 体积最小（~5MB）
- 内存占用最低（~10MB）
- 启动速度最快

**缺点**：
- 外观比较朴素，像 Windows XP/7 时代的程序
- 不能自定义主题颜色
- 没有动画效果
- 控件样式固定，美化空间有限

### 适合场景

追求**实用、小巧、不花哨**的工具类程序。用户不关心界面好不好看，只要能用就行。

- 内存占用较高：~20-40MB
- Windows 专属

### 适合场景

希望界面**好看、专业**，愿意接受较大体积。

PySimpleGUI 基于 tkinter，外观是**tkinter 默认风格**：

│  运营商: [校园用户      ▼]          │

│  检测间隔: [30] 秒                   │
│                                     │

│                                     │
│  ┌─────────────────────────────┐    │
│  │ [INFO] 17:30:00 已连接      │    │

- 内存占用最高（~40-80MB）

- 容易被杀毒软件误报
- tkinter 外观比较"土"

### 适合场景

快速原型验证，对体积无要求。

- 界面最漂亮，可以用 HTML/CSS/JS 做任意美化

- 跨平台（Windows/Mac/Linux）

**缺点**：
- 需要 Rust + 前端双栈（Rust 后端 + HTML/CSS/JS 前端）
- 学习曲线最陡
- 编译慢
- 依赖系统 WebView2（Win10/11 自带，Win7 需要安装）

### 适合场景

追求**最美观**的界面，有前端开发经验。

## 资源占用详细对比

### 磁盘体积（打包后）

| 方案 | exe 体积 | 说明 |
|------|----------|------|
| Go + walk | **~5MB** | 单个 exe，无依赖 |
| Rust + tauri | **~3-5MB** | exe + WebView2 运行时（系统自带） |
| C# WinForms | **~15-20MB** | 自包含 .NET 运行时 |
| C# WPF | **~20-30MB** | 自包含 .NET 运行时 + WPF 框架 |
| Python + PySimpleGUI | **~30-60MB** | 打包 Python 解释器 + tkinter + 依赖库 |

### 运行时内存占用（idle 状态，即后台待机）

| 方案 | 内存占用 | 说明 |
|------|----------|------|
| Go + walk | **~5-10MB** | Go 编译的原生程序，无运行时开销 |
| Rust + tauri | **~15-25MB** | WebView2 进程占用（系统 WebView） |
| C# WinForms | **~15-25MB** | .NET CLR 运行时 + GC 开销 |
| C# WPF | **~25-40MB** | .NET CLR + WPF 渲染引擎 + DirectX |
| Python + PySimpleGUI | **~30-60MB** | Python 解释器 + tkinter + 内存管理 |

### 运行时 CPU 占用（idle 状态）

| 方案 | CPU 占用 | 说明 |
|------|----------|------|
| Go + walk | **~0%** | 原生程序，idle 时几乎不消耗 CPU |
| Rust + tauri | **~0-0.5%** | WebView 有少量后台开销 |
| C# WinForms | **~0-0.5%** | .NET GC 偶尔触发 |
| C# WPF | **~0-1%** | WPF 渲染引擎 + 动画线程 |
| Python + PySimpleGUI | **~0-1%** | Python 解释器 + GC |

### 启动速度

| 方案 | 启动时间 | 说明 |
|------|----------|------|
| Go + walk | **< 0.1秒** | 原生程序，瞬间启动 |
| Rust + tauri | **~0.5-1秒** | WebView 初始化 |
| C# WinForms | **~0.3-0.5秒** | .NET JIT 编译 |
| C# WPF | **~0.5-1秒** | .NET JIT + WPF 初始化 |
| Python + PySimpleGUI | **~1-3秒** | Python 解释器启动 + 模块加载 |

### 常驻后台场景（你的需求：24小时保活）

对于校园网保活工具，程序大部分时间处于 **idle 状态**（等待定时检测），关键指标是：

| 方案 | idle 内存 | 24h 后内存 | 磁盘读写 | 备注 |
|------|-----------|------------|----------|------|
| Go + walk | 5-10MB | **5-10MB**（无增长） | 极少 | 最稳定，无 GC 抖动 |
| Rust + tauri | 15-25MB | **15-25MB**（无增长） | 极少 | WebView 稳定 |
| C# WinForms | 15-25MB | **15-30MB**（GC 波动） | 少 | .NET GC 会周期性回收 |
| C# WPF | 25-40MB | **25-45MB**（GC 波动） | 少 | WPF 渲染引擎持续占用 |
| Python | 30-60MB | **30-70MB**（可能泄漏） | 少 | Python GC 不够激进 |

## 我的推荐

根据你的需求（小巧 + 有 GUI + 单文件 exe）：

1. **如果追求极致小巧** → Go + walk（5MB，朴素但够用）
2. **如果想要界面好看** → C# WPF（20MB，现代扁平风格）
3. **如果想要最小体积又好看** → Rust + tauri（3MB，网页风格，但开发难度高）
4. **如果想快速开发** → C# WinForms（15MB，拖控件即可）
